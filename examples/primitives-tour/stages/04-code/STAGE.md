### 段 4 · 闰年判断

> 核心教学事件：学生把"闰年"的三条规则写成一个函数，用自动测试检验自己的代码；教师把典型代码投到大屏讲评，必要时亮出参考答案。

**A 展示**
- 大屏投什么：已运行 N/M（在线）、测试全过 N、最近报错 Top 3（按报错首行聚合，带次数）；教师从统计页投上来的某个学生的代码与输出（上交了最终稿就投最终稿）；点"显示参考答案"后显示参考答案
- 学生屏幕看什么：右栏"题目"面板（题目、三条要求可自己勾选、[上交最终稿] 与上交状态；窄屏时 [上交最终稿] 在底部操作条），左边"代码"编辑器（起始代码已写好函数骨架）与"输出"区、[运行] [停止] [测试] 按钮；测试后输出区变"测试结果"：通过 x / 4 与每个用例一行 ✓ / ✗（失败给一行原因），pytest 原文收在"查看详细输出"里；窄屏时题目在上、可折叠；底部操作条显示"已记录 · 测试 x / 4"
- 教师按什么按钮、在什么时点按：统计页点某生 → "投到大屏"讲评；演示页"显示 / 隐藏参考答案"、"取消展示"；测试全过的人数够了按"下一段"（见 E）
- 教师是否需要看某个学生的实时画面 / 挑人上来讲：统计页点行看该生代码与输出；可镜像；挑一份代码投大屏讲

**B 学生做什么**
- 动作是什么：改代码 → 运行看输出 → 测试 → 满意了点"上交最终稿"
- 有几步，步与步之间是否有先后：运行和测试随时可点，没有先后；每次结束自动记录；上交最终稿要确认一次
- 提交后能不能改：能；自动记录以最后一次运行 / 测试为准，最终稿可再次上交覆盖
- 做不对时平台给什么反馈：Python 报错 + 中文提示；测试显示"通过 x / 4"与失败用例的原因（如 `assert is_leap(1900) is False → 实际 True`）

**C 采集**
- 记什么字段：每人 `code`、`stdout`、`error`、`tests { passed, failed, errors, total, cases }`、`runs`、`ms`、`submittedAt`、最终稿 `final` 与 `finalAt`；班级 `featured`（投到大屏的学生）、`showSolution`（开关）
- 记到人、记到组、还是只记到班：到人 + 到班（大屏展示状态）
- 课后要不要回看 / 进个人报告：可回看（只读）；进个人报告：测试通过数 / 总数、我的代码（有最终稿用最终稿）

**D 统计**
- 教师统计视图看哪几列：姓名、运行次数、最近报错、测试 通过/总数、已上交、最近运行；顶部摘要：已运行 N/M、无报错 N、已上交 N/M、测试全过 N；点行看"最终稿 / 最近运行"两个标签，可"投到大屏"
- 什么情况要提醒教师走过去：进入本段 8 分钟仍未测试全过
- 要不要排行 / 推荐分享：不排行；推荐分享列最早测试全过的 5 人

**E 推进条件**
- 教师按"下一段"时要满足：在线学生里测试全过的 ≥ 70%
- 不满足时：软提示（一键继续 / 可强制推）

**匹配原语**：code

**页面样式**：split
