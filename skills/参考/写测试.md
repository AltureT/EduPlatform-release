# 写测试（代码题的测试与参考答案）

用在：`code` 原语段写 `options.tests`，或自写段写 `sandbox.tests`。关一（`check:lesson`）会用参考答案跑一遍测试，再把答案"改坏一处"看测试抓不抓得住。

## 1. 先写参考答案，再列输入

- `code` 段：答案写在本段目录 `solution.py`，`options` 里写 `solution: { from: './solution.py' }`（只发教师）。
- 自写段：答案放本段目录 `solution.py`（不被 `stage.config.js` 引用，不进学生页面）。
- 答案写成学生该写成的样子：同样的函数名、同样读 `input()` / 同样打印。

## 2. 用例从哪来

- 阶段卡里教师给的例子必须各有一条；再补：正常情况、边界（等于分界值、空、0、最大最小）、反例（不该算对的情况）各至少一条；合计至少 3 个 `def test_`。
- 期望值不要猜：写完跑关一，参考答案过了才算数。

## 3. 两个模板（照抄后改名字和数据）

函数题（学生写函数）：

```python
from main import grade

def test_normal():
    assert grade(75) == '及格'

def test_boundary():
    assert grade(90) == '优秀'
    assert grade(89) == '及格'

def test_counter():
    assert grade(59) == '不及格'
```

输入输出题（学生用 `input()` 读、用 `print()` 打印）：

```python
import runpy

def run_main(monkeypatch, capsys, *lines):
    feed = iter(lines)
    monkeypatch.setattr('builtins.input', lambda prompt='': next(feed))
    runpy.run_path('main.py', run_name='__main__')
    return capsys.readouterr().out

def test_normal(monkeypatch, capsys):
    assert run_main(monkeypatch, capsys, '3', '4').strip() == '7'

def test_negative(monkeypatch, capsys):
    assert run_main(monkeypatch, capsys, '-1', '1').strip() == '0'

def test_zero(monkeypatch, capsys):
    assert run_main(monkeypatch, capsys, '0', '0').strip() == '0'
```

## 4. 关一结果怎么改

- `参考答案没通过测试：<用例>（<原因>）` → 先判断是答案错还是测试错，改对的那一边；不能删测试凑过。
- `测试抓不住 k/m 个改坏的版本（如 …）` → 按列出的例子补用例（多半是分界值没测到）。
- `只有 N 个测试用例` → 按第 2 条补齐；`有测试但没有参考答案` → 按第 1 条放答案。
- `隐藏用例还没生成` / `已过期` / `错误库 … 还没生成` / `已过期` → 跑 `npm run prep:tests -- <段目录>`；`没列进测试` → 照提示把那一行加进 `tests`。
- `错误版本"…"没被测试抓住` → 补一条让它失败的用例（测试或隐藏用例）；`… 失败的用例一样，上课分不开` → 补一条只让其中一个失败的用例；再跑 prep。
- `笨办法解没通过测试：…` → 题意可能有歧义：对照那几条用例，改错的那一个（答案、笨办法解或测试），不删测试。
- `Python 运行时还没下载，… 的测试没验证` → 不是课的问题；告诉教师（放进下一条消息里）：

发给教师（只发下面引用块的内容，不带这一行、不带引用格式）：
> 这节课的代码题还差一步验证，要先这样做：
>
> 1. 到工作台左边第 4 步"上课准备"；
> 2. 在"Python 运行时"一节点"开始下载"（约 40 MB，需要联网）。
>
> 下载好告诉我，我再检查一遍。

- 同一条改了三次还在 → 按 `skills/SKILL.md`"做不到的时候"处理。

## 5. 提醒

- 测试文件学生看得到，是帮学生自查的，不要写成保密判分。
- 测试里不要真的等 `input()`、不要死循环、不要读网络；数据量小，一个用例一眨眼跑完。
- 函数题的起始代码和参考答案把 `input()` 放进 `if __name__ == '__main__':` 里，否则测试 `from main import …` 时会卡在等输入。

## 6. 隐藏用例（防照着测试硬编码）

- 何时写：题目输出不是一眼能猜的（不是只有 True / False 几种），且怕学生照着看得见的测试写死答案。正例：`examples/python-intro` 过测试段的两条（`grade(100)`、`grade(0)`，返回等级文字）；示例课闰年段（返回 True / False）只作演示，这种题写不写都行。
- 本段目录写 `hidden.json`（≤ 30 条），期望值不写，由参考答案算：`[{ "name": "整百年不是闰年", "call": "is_leap(1900)" }, { "name": "两数相加", "stdin": ["3", "4"] }]`——`call` 是函数题的调用表达式，`stdin` 是输入输出题逐行喂给 `input()` 的内容；`name` 1–30 字、不重复。
- 跑 `npm run prep:tests -- <段目录>`：生成 `tests/test_hidden.py`（只存哈希，不要手改）。
- 把它列进测试：code 段 `tests: { …, 'test_hidden.py': { from: './tests/test_hidden.py' } }`；自写段把文件全文抄成字符串常量放进 `sandbox.tests`。参考答案或 `hidden.json` 改了就重跑 prep。

## 7. 错误库（上课时自动把学生的错归类）

- 先想"学生最常错在哪"，写 2–4 个错误版本：本段目录 `mistakes/<名字>.py`（小写字母、数字、`-`、`_`），开头两行 `# 错误：<1–20 字类型名>`、`# 提示：<≤ 200 字，给 AI 助手引导用>`，其余写成学生最可能写成的样子，完整能跑。
- 跑 `npm run prep:tests -- <段目录>`：生成 `mistakes.json`；code 段 `options` 里写 `mistakes: { from: './mistakes.json' }`（只给老师看，统计页按类型分组）。自写段也可以放 `mistakes/`，但不做上课时的归类，只用来检查测试抓不抓得住这些错。
- prep 或关一报"没被测试抓住" / "上课分不开" → 补用例（§2、§6）再跑。

## 8. 对拍（可选）

- 答案有技巧、或教师给的例子少时，本段目录再写一份 `brute.py`：同样的函数名 / 输入输出，用最笨最直白的写法（逐条 if、暴力枚举）。
- 关一用它跑全部测试，prep 用它对隐藏用例；不一致说明题意有歧义或某一份写错了，先弄清题意再改。
