# 04 执行与审查（一次只做一段）

## 进入条件

- 读 `lessons/<id>/进度.md`："环节"里有 `03 脚手架与计划：✓`。没有 → 回 `skills/03-脚手架与计划.md`。
- 在"阶段表"里从上往下找第一个"内容 / 检查 / 模拟 / 审查"里有一格**恰好是 `✗`**（不带括号原因）的段，它就是"本段"。写着 `✗（<原因>）` 的格子已记进后续定制，不再选它。
  - "内容"是 `✗` → 从本文件"做本段"开始；
  - "内容"是 ✓、后面某格是 `✗` → 直接从那一关开始（"三关"）。
- 找不到这样的段 → 本环已完成，跳到文末"本环完成标志"。
- 铁律全文见 `skills/SKILL.md`，本环最常碰到的是第 3、4、6、8 条。

## 一轮 = 做本段 → 三关 → 存档 → 写进度 → 回到"进入条件"取下一段

- 原语段做完不请教师看，攒着：`进度.md`"待办与后续定制"加一行 `- 待教师看：第 <N> 段`。
- 专门做的段（`none`）在关三请教师看一次：连同攒着的段，和审查放在同一条消息里。
- 教师说过"做完一起看"→ 整环只在最后看一次（05 环第 3 步），关三那条消息里不请他看。

能另开新上下文助手的工具可以并行做自写段，见 `skills/参考/子代理加速.md`；没有就照本文件一段一段做。

阶段表"原语或自写"是 `组件` 的行（课程组件）：按自写段流程做（三关 + 新对话审查），细节见 `skills/参考/课程组件.md`。

### 做本段 · 原语段（阶段表"原语或自写"是原语名）

1. 读 `primitives/<原语>/README.md` 的"options"表和"示例"。
2. 打开 `lessons/<id>/stages/NN-<段id>/stage.config.js`，照示例改 `options`，对照本段 `STAGE.md`：
   - 题目、选项、答案、解析、提示都写在 `options` 里，不写进别处（铁律 4）；
   - 题目一句话放 `question`；短信原文、情境、阅读材料等长文放 `prompt`（投票、小测、写一段话都有，显示在标题下方），不要把长文塞进 `question`；
   - B 栏"提交后能不能改"、E 栏门槛（`skills/参考/选项话术.md`"推进门槛"的 `gate` 写法表）、D 栏提醒时间 → README 表里对应的键（表里没有的不写）。
3. 所有 `TODO` 换成本课内容；示例里的原题（例如质数题的选项、`answer: 'C'`）也要换成本课的，不能留。
4. 要用文件（起始代码、测试、数据表）：放在本段目录里，写 `{ from: './<文件名>' }`；几段共用的放 `lessons/<id>/stages/_shared/`，写 `{ from: '../_shared/<文件名>' }`（代码题的测试、隐藏用例、错误库按 skills/参考/写测试.md 写；有 hidden.json 或 mistakes/ 时跑 npm run prep:tests -- <段目录>）。
5. 原语段只能改 `options`，不能换页面：不写 `collect`、`subPhases`、`layout`、`sandbox`，不放 `Student.jsx` 等视图文件。教师要改页面的样子（字的大小、摆放、加图）→ 用选项话术"改法做不到时"那句，记进 `平台规格.md`"后续定制"。
6. 只有 `vote` 段选了"揭晓才能进"时，照下面"揭晓之后才能进"再写两处。
7. 完成标志：本段目录里（含子目录的文件）都搜不到 `TODO`；阶段表本段"内容"改 ✓。

**揭晓之后才能进**（`vote` 且有 `answer`）：删掉 `options` 里的 `gate`；在 `stage.config.js` 里与 `options` 同一层加下面这段（`<比例>` 七成写 `0.7`、全部写 `1`；`<软硬>` 一键继续写 `true`、再确认一次写 `false`；比例选"不设"就删掉中间 `const on` 到 `if` 三行）：

```js
  gate(ctx) {
    if (ctx.state.subPhase !== 'reveal') return { ok: false, soft: false, reason: '还没揭晓' };
    const on = ctx.state.connected();
    const done = on.filter((s) => ctx.data.get(s.name)?.choice != null).length;
    if (done < Math.ceil(on.length * <比例>)) return { ok: false, soft: <软硬>, reason: `已投 ${done}/${on.length}` };
    return { ok: true };
  },
```

再建 `lessons/<id>/stages/NN-<段id>/__tests__/simulate.js`（模拟时让虚拟教师点"揭晓"，否则关二过不了），原样抄：

```js
import { waitForMatching } from '#kernel/test-utils/index.js';

export async function play({ students, teacher, ctx }) {
  const { id, options } = ctx.stageConfig;
  const key = options.choices[0].key;
  await Promise.all(students.map((s) => {
    const ack = waitForMatching(s.socket, 'stage:my-data', (p) => p?.stageId === id, 5000);
    s.send('student:vote', { choice: options.multiple ? [key] : key });
    return ack;
  }));
  const revealed = waitForMatching(teacher.socket, 'stage:sub-phase', (p) => p?.subPhase === 'reveal', 5000);
  teacher.send('teacher:reveal', {});
  await revealed;
}
```

### 做本段 · 自写段（阶段表"原语或自写"是 `none`）

1. 读四样：`lessons/<id>/plans/<段id>.md`、本段 `STAGE.md`、`docs/02-阶段模块契约.md` 的 §一 至 §四 与 §七、`docs/05-样式约定.md`。照 `examples/minimal/stages/02-freeform/` 的写法写。
2. 在 `lessons/<id>/stages/NN-<段id>/` 里改 / 写这些文件，把 `new:stage` 留下的 `TODO` 全部换掉：
   - `stage.config.js`：`layout`（= 页面样式）、`gate`（E 栏）、`collect`（C 栏）、`alerts`（D 栏提醒）；C 栏说"进个人报告"→ 写 `summarize`，只返回卡里要的条目、标签用中文（不写就会把每个字段原样放进报告）；
   - `stage.config.js` 的 `components`：A 栏没要求"看某个学生的画面 / 挑人分享"→ 写 `components: [<平台规格.md 本段"触发的组件"，没有就空着>]`，只留要的（`用 AI` 不是组件，不写进 components）；A 栏有要求 → 不写这一行（全开）；
   - 学生做错时：`server.js` 里用 `ctx.reject(socket, '<一句为什么没成功>')`，平台会把这句话在学生屏顶部显示几秒，学生页不用自己显示；
   - `server.js`：计划里的事件；记录里不写学生姓名；
   - 平台规格本段有 `用 AI：是`（段里要让 AI 点评 / 生成 / 判断）→ 只在 `server.js` 里 `ctx.ai.chat`，提示词写成文件顶部中文常量；写清没配 AI 时这段怎么上（`ctx.ai.configured` 为 false 时照常记录、不报错）；不自己连接口、不写地址密钥、学生页不调 AI（契约 §三"调 AI"）；
   - `Student.jsx`：根是 `<Page>`，`template` 与 `layout` 相同，主按钮放 `<Page.Actions>`；
   - `Student.jsx` 里学生输入的东西（文本框、输入框、勾选、滑块、没交的作答）一律用 `useDraft`，不用 `useState`（契约 §四"学生输入自动保存"）：刷新、断线、换设备都不丢；没改过时显示已提交的记录，提交成功后调 `clear()`。照 `examples/minimal/stages/02-freeform/Student.jsx` 写；`npm run check:ui` 会对有输入框却没用 `useDraft` 的学生页给提醒；
   - `TeacherStats.jsx`：表格列 = D 栏；
   - 教师的"演示视图"就是这一段的学生页（平台自带），**不用写 `TeacherDemo.jsx`**；要让老师在大屏上当众点选 / 提交，`Student.jsx` 在 `useStudentStage().demo` 为真时改用 `setMyData({ … })` 写本地记录（不处理也行，演示时只是不能提交）；
   - 揭晓、取消展示这类老师按的按钮：写在 `TeacherActions.jsx`（`export default function TeacherActions({ stageId })`，返回几个按钮），平台放在底部操作条上；不需要就不建；
   - `__tests__/server.test.js`：每个事件一条正向、一条被拒；gate 通过、不通过各一条；
   - `__tests__/simulate.js`：让每个虚拟学生做到能过门槛。
3. 跑 `node --test lessons/<id>/stages/NN-<段id>/__tests__/server.test.js`
   - 完成标志：输出末尾有 `fail 0`（不同 Node 版本前面是 `ℹ` 或 `#`）。有失败 → 按报错改代码或测试，再跑。
4. 确认学生页能打开：跑 `npm run build:lesson -- lessons/<id>/lesson.config.js`（把这门课的页面打包到系统临时目录，不动平台自己的）。
   - 完成标志：最后一行是 `通过：页面能打包`（中间"chunks are larger than 500 kB"那段提示是正常的）。
   - 最后一行是 `打包失败……` → 按上面报错里指到的文件和行改，再跑。
5. 阶段表本段"内容"改 ✓。

### 三关（两类段都要过，按顺序；一关不过不进下一关）

**关一 · 检查**：跑 `npm run check:lesson -- lessons/<id>/lesson.config.js`

- 完成标志：最后一行以 `通过` 开头，且没有一行"警告"指向本段目录（后面还没做的段有 TODO 警告是正常的）。本段是代码题时还要有一行"代码题测试：段 <id> 通过"。
- 有"错误"行，或本段有"警告"→ 照那一行"→"后面的话改，再跑。同一行改了三次还在 → 按 `skills/SKILL.md`"做不到的时候"处理，本段"检查"写 `✗（<原因>）`，去做下一段。
- 通过 → 本段"检查"改 ✓。

**关二 · 模拟**：跑 `npm run simulate -- --lesson lessons/<id>/lesson.config.js --students 5`

- 完成标志：最后一行是 `=== RESULT: PASS (exit 0) ===`，上面表格里"阶段"列为本段段id 的那一行，"gate"列是 `通过`。
- 不是 PASS → 看表格"说明"列。常见原因：`simulate.js` 没让虚拟学生做到门槛要求的动作；`gate` 算错；`options` 的门槛写错。改完重跑关一、关二。三次仍不过 → 同关一的处理，"模拟"写 `✗（<原因>）`。
- 通过 → 本段"模拟"改 ✓。

**关三 · 审查**

- 两类段都先看：关一的 `check:lesson` 有一行报"平台文件被改过"→ 审查不通过，把改动挪回课程目录 `lessons/<id>/`（平台文件恢复原样），重跑关一、关二。
- 原语段：你自己按 `skills/参考/审查清单.md`"原语段"一节逐条核对。有差异就改，改完重跑关一、关二。都对 → 本段"审查"写 `✓自审`。
- 自写段：必须由一个新对话审查（它没看过你写的过程）。
  1. 跑 `node -e "console.log(process.cwd())"`，打印的是平台目录的完整位置。
  2. 生成"审查粘贴文本"，按顺序拼五块：① 一行 `平台目录：<打印的位置>`；② `skills/参考/审查清单.md` 全文；③ 一行 `阶段目录：lessons/<id>/stages/NN-<段id>/`；④ 一行 `平台规格中本段：` 加 `平台规格.md` 阶段表本段那一行；⑤ 一行 `阶段卡：` 加本段 `STAGE.md` 全文。存为 `lessons/<id>/plans/<段id>-审查.md`。
  3. 发一条消息：先用选项话术"去工作台看"固定句，<看什么> 换成"进教师端看第 <本段和攒着的段号> 段，学生看到的样子点工作台上的学生地址看"（教师说过"做完一起看"就不加这句）；再接下面这句，然后把粘贴文本原样放在一个代码块里：

发给教师（只发下面引用块的内容，不带这一行、不带引用格式）：
> 另外请你帮个忙：
>
> 1. 在你现在用的这个 AI 工具里新开一个对话，
>    - 同样打开这个平台所在的位置；
> 2. 把下面这一整段贴进去；
> 3. 等它回答完，把它的回答整段贴回来给我。
>
> 看的时候有要改的，也一起告诉我。

  4. 这条消息里请看的段，从 `进度.md` 删掉对应的 `- 待教师看：` 行。
  5. 教师贴回的回答第一行是 `通过` → 本段"审查"改 ✓。
  6. 第一行是 `不通过` → 按每条差异的"建议改"改 → 重跑关一、关二 → 重新生成粘贴文本，请教师再贴一次。最多 3 轮；第 3 轮仍不通过 → 按"做不到的时候"处理，"审查"写 `✗（<原因>）`。
  7. 差异里写着"请教师确认：……"的：不问教师，你按常理定、照着改，在 `平台规格.md`"决策记录"记一行（教师选择写 `由 AI 默认：<你定的>`），在你下一条要发给教师的消息里用一句话告诉他；教师不同意再改。

教师看了说要改 → `skills/参考/改课.md`（本段还在做、没存档时直接改，不走它）。改法做不到 → 选项话术"改法做不到时"。

### 存档

1. 跑 `git add lessons/<id>`
2. 跑 `git commit -m "<课名>：第 <N> 段 <阶段名>"`
3. 完成标志：打印的第一行含 `第 <N> 段`。本段"存档"改 ✓。报错 → 跳过 git，本段"存档"写 `未存档`。

### 写进度（每段一次）

- 阶段表本段：内容、检查、模拟、审查、存档都已按上面改好；
- 最近一次停在：`04 第 <N> 段 <阶段名> 完成`
- 下一步：`04 第 <N+1> 段 <阶段名>`（这是最后一段就写 `05 第 1 步：全程模拟`）
