# 排障手册

> 读者：老师贴来排障文件（平台文件夹 `排障/` 里的 `<日期>-<时分秒>-<环节>.md`，或老师说"启动失败 / 打不开 / 更新失败"）时的 AI 开发工具。教师不需要读。
> 作用：按这一页把问题分成环境、课程、平台三类，环境与课程问题当场给老师办法，平台问题写反馈文件交回给我们。排障文件由班迹工作台或双击入口自动写，结构见下面"一"。
> 规矩不变：不改平台文件（`kernel/`、`components/`、`primitives/`、`scripts/`、`docs/`、`skills/`、根上的入口文件），不打补丁。

## 一、先做三件事

1. 读排障文件的"发生了什么"（环节、一句话、详情）与"环境"（班迹版本、平台文件被改过、系统、Node、平台文件夹与真实路径、磁盘、当前课程、`.env` 键名）。"最近记录"里的构建输出、运行记录、入口脚本记录、npm 记录是判断依据。环节是"启动入口"或"安装依赖"的文件由双击入口写，"平台文件被改过"写"没查"、工作台写"没启动"，属正常。
2. 对照下面"三、已知问题表"：班迹版本落在某行的版本区间、症状也对得上，就直接给那一行的处理，不再往下查。
3. 按下面"二、三类问题"判断是环境、课程还是平台问题。判断依据要写得出来（引用排障文件里的哪一行、哪个关键字），对不上任何一类就说"看不出来"，按平台问题写反馈文件，不猜。

## 二、三类问题

### 环境问题

AI 直接给老师可操作的办法，不动任何文件。

- 典型症状（日志里的关键字）：
   - Node 没装或太旧：环节"启动入口"且一句话含"没有可用的 Node.js"；`Node 未找到`；Node 主版本 < 22。
   - 端口被占：`EADDRINUSE`、"端口被占"。工作台页面本身有按钮处理，排障文件里少见。
   - 平台文件夹在网络盘、共享盘或外接盘："真实路径"以 `\\` 或 `/Volumes/` 开头，或带"（网络盘或外接盘）"；Vite 报 `./U:/…` 这类跨盘符路径；`EISDIR`、`ENOTSUP` 出在平台文件夹里。
   - 依赖是在别的电脑上装的（`node_modules` 从别的系统或芯片拷来，或平台文件夹在虚拟机共享文件夹里被两边用）：窗口里有"依赖和这台电脑不配，正在重新安装…"，或"重装后仍不能用，请把 node_modules 文件夹整个删掉再双击"（排障文件环节"安装依赖"、一句话含"工作台退出码 77"）；记录里有 `ERR_DLOPEN_FAILED`、`not a valid Win32 application`、`incompatible architecture`、`wrong ELF class`、`Cannot find native binding`、`Cannot find module '@rolldown/binding-…'`。
   - `npm install` 失败（环节"安装依赖"）：`ETIMEDOUT`、`ECONNRESET`、`EAI_AGAIN`、`ENOTFOUND`（网络）；`better-sqlite3` 二进制下载失败（`prebuild-install`、`better_sqlite3.node`）；`EPERM`、`EBUSY`、`EACCES`（杀毒软件或文件被占）。
   - 防火墙：平台启动成功但学生连不上。
   - Mac"无法打开"或"无法验证开发者"。
   - 磁盘空间：`ENOSPC`，或"磁盘可用"不到 500 MB。
   - 平台文件被改过：环境里"平台文件被改过：是"，或课程检查报"平台文件被改过"。
   - Python 环境没准备好：环节"下载运行时"，一句话是"Python 环境没准备好：<原因>"；下载记录里有 `ETIMEDOUT`、`ENOTFOUND`、`ECONNRESET`、`fetch failed`（网络）或 `ENOSPC`（磁盘）。
- 判断依据：上面的关键字出现在"详情"或"最近记录"里，报错栈不落在 `lessons/<id>/`；或"环境"一节直接给出了原因（真实路径、Node 版本、磁盘）。
- AI 能做什么：
   - Node：让老师双击时按回车自动下载；不想自动下载就到 nodejs.org 装 22 或 24 版。
   - 网络盘 / 外接盘：让老师把整个平台文件夹拷到本机磁盘（比如桌面或文稿）再双击。
   - 网络类安装失败：换国内源安装，命令见 `docs/技术同事.md` §五（`better-sqlite3` 二进制同样用那里的镜像）；或让同系统、同芯片的同事把装好的 `node_modules` 整个拷过来。
   - 依赖是在别的电脑上装的：双击入口会自动重装一次；重装后仍不行，让老师把平台文件夹里的整个 `node_modules` 删掉、联网后再双击（会从头装）。虚拟机共享文件夹里的平台文件夹，两边各拷一份到本机磁盘用。
   - `EPERM` / `EBUSY`：关掉杀毒软件的实时防护或把平台文件夹加进白名单，关掉占着文件的程序（编辑器、另一个工作台窗口），再双击。
   - 防火墙、Mac"无法打开"：按 `docs/技术同事.md` §一、§二的步骤。
   - 磁盘空间：清出空间再双击。
   - 平台文件被改过：重新解压同一版本的发布包覆盖平台文件夹（课程、数据、设置不会丢）。
   - Python 环境没准备好：看排障文件里的下载记录。网络问题让老师换个网络（例如手机热点），或让同事把运行时整包（`EduPlatform-runtime-v<版本>.zip`）拷来放进平台文件夹的 `vendor` 文件夹；然后到工作台 平台 → 环境与版本 点"重试"。磁盘不够先清出空间再重试。
- 对老师说什么：一两句结论加下一步，例如"平台文件夹放在了共享盘上，那里装不了。把整个平台文件夹拷到桌面，再双击里面的班迹工作台。"

### 课程问题

在做课 skill 的范围内，AI 直接改 `lessons/<id>/`。

- 典型症状：课程检查结果里有"错误"；构建输出或平台运行记录里的报错栈落在 `lessons/<id>/` 或课程自己的 `lessons/<id>/components/`；`lesson.config.js` 加载不了（`SyntaxError`、`Cannot find module './stages/…'`、`is not exported`）。
- 判断依据：报错栈第一个不在 `node_modules/` 里的位置在 `lessons/<id>/` 下；或"课程检查结果"一节列出了错误。"当前课程"一行给出了是哪门课。
- AI 能做什么：按报错改 `lessons/<id>/` 下的文件（写法照 `docs/02-阶段模块契约.md`、`docs/06-组件契约.md`）；改完跑 `npm run check:lesson` 与 `npm run build:lesson`，都通过后让老师在工作台重新"启动平台"。
- 对老师说什么：说哪一段出了什么问题、已经改好，请他回工作台再点一次"启动平台"。不说文件名和报错原文。

### 平台问题

AI 不改平台文件，这条规矩不变。

- 典型症状：报错栈落在 `kernel/`、`components/`、`primitives/`、`scripts/`；环节是"工作台启动"（工作台自身启动失败）；环节"更新"且更新失败已回滚；Vite 报错指向平台文件；"平台退出"且运行记录里的栈在平台文件里。
- 判断依据：报错栈第一个不在 `node_modules/` 里的位置在上面这些目录下，且"平台文件被改过"不是"是"（是的话先按环境问题重新解压覆盖）。
- AI 能做什么，两件事：
   - 能绕就给临时绕法：例如拷到本机磁盘；退回旧版本（`docs/技术同事.md` §三）；换一门课先上。
   - 写反馈文件 `排障/<原文件名去掉 .md>-反馈.md`（格式见下面"四"），让老师发到发布仓库的 Issues：GitHub `https://github.com/AltureT/EduPlatform-release/issues`，国内用 Gitee `https://gitee.com/alture/EduPlatform-release/issues`。反馈文件不会被自动清理。
- 对老师说什么：这是平台自己的问题，不是你的操作或课程的问题；先给临时办法；再说"排障文件夹里多了一份'反馈'，把它发到发布页的问题反馈里，我们会修"。

## 三、已知问题表

版本号对得上、症状也对得上就直接给处理。以后每个热修加一行。

| 版本区间 | 症状 | 处理 |
|---|---|---|
| ≤ v0.6.1，从旧版更新而来 | 平台文件夹里还留着旧的双击入口；或 Mac 双击 `.command` 提示没有执行权限、打不开 | 升到 v0.6.1 以上：重新下载最新发布包，解压覆盖平台文件夹 |
| v0.6.1，Windows | 平台文件夹在共享文件夹（UNC 路径 `\\…`，例如虚拟机里共享的 Mac 桌面），双击后 `cd /d` 失败、打不开平台文件夹 | 升到 v0.6.2；或先把平台文件夹拷到本机磁盘 |
| ≤ v0.6.2，Windows 网络盘 | 启动平台时构建失败，Vite 报 `./U:/…` 这类跨盘符路径，`import.meta.glob` 找不到课程 | 升到 v0.6.3；或先把平台文件夹拷到本机磁盘 |
| ≤ v0.8.4 | Windows 上课程检查显示"Python 环境还没准备好 / 测试没验证"，环境其实已就绪（Pyodide 在 Node 里从反斜杠路径推包目录失败，pytest 装不上；只影响 AI 侧的代码题测试验证，课堂里的学生沙盒不受影响） | 升到 v0.8.5 以上 |
| 所有版本 | 上课记录保存失败 / `database is locked` / `disk I/O error`，平台文件夹在共享文件夹或网络盘 | 把整个平台文件夹拷到本机磁盘，再从那里双击工作台 |

## 四、反馈文件格式

文件名 `排障/<原排障文件名去掉 .md>-反馈.md`，Markdown，依次：

1. 标题：一句话现象 + 班迹版本，例如 `# 启动平台时构建失败（v0.6.3）`。
2. 环境四行：班迹版本；系统；Node 版本；平台文件夹是否在网络盘或外接盘。
3. 复现步骤：老师做了什么（双击、点了哪个按钮），一步一行。
4. 已排除的原因：AI 查过什么、为什么不是环境或课程问题。
5. 关键记录：从排障文件里摘 ≤ 30 行，原样（排障文件已脱敏，不要再加回任何密码、密钥）。
6. AI 的推测与建议：可能是哪里的问题、怎样复现、临时绕法。

## 五、AI 可以跑的命令

- 可以跑：`node -v`、`npm -v`、`npm run check:lesson`、`npm run build:lesson`（都在平台文件夹里跑）。
- 不跑：`npm run manage`、`npm run server`、`npm run dev`（会占端口、动 `.env`，和老师的工作台抢）。
- 不删 `node_modules`，不改 `.env`，不动 `data/`、`backups/`、`vendor/`；排障文件夹里只新建反馈文件，不改、不删排障文件。

## 六、对老师说话

- 规矩同 `skills/SKILL.md`"对教师说话"：只说结论和下一步，一句一行，不用加粗、标题、表格。
- 不露文件名、路径、命令、版本号、报错原文。要老师做的操作用"平台文件夹""拷到桌面""双击班迹工作台""在工作台点'启动平台'"这类说法。
- 反馈文件可以说"排障文件夹里多了一份'反馈'"，发到哪里说"发布页的问题反馈"。
- 一次只发一条消息；要老师做的事编号写，一步一行。
