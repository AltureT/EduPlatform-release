> 读者：AI（主代理、子代理、审查者）。教师不需要读。
> 作用：规定"一个阶段"在代码里长什么样，使得一张阶段卡可以被一个子代理独立实现，并被另一个子代理独立审查。契约冻结后，阶段之间不允许直接 import。

## 一、目录结构与 import 方式

> 先看总览：平台分哪几层、哪些能复用 / 自定义 / 不能动、从哪开始，见 `docs/00-框架地图.md`（一页）。跨段或旁挂的功能做成组件，写法见 `docs/06-组件契约.md`（v0.8.10）。

用户项目 = 模板仓库的副本：

```
<项目根>/
  package.json                  # "imports": { "#kernel/*": "./kernel/*", "#components/*": "./components/*", "#primitives/*": "./primitives/*" }（v0.6 增 #components，v0.8 增 #primitives），Vite / 测试同名别名（@primitives）
  lesson.config.js              # 课名、阶段顺序、名单模式、主题、组件开关
  kernel/                       # 内核，用户与 AI 均不改；只允许通过三个公开入口引用
  components/                   # 可选组件，按 lesson.config 开关
  primitives/                   # 活动原语（v0.8，见 §五），阶段用 stage.config.primitive 选用
    _shared/                    # 原语作者用的共享件（gate.js 声明式门槛、StatsPage.jsx 统计骨架），不对阶段公开
```

## 三、server.js 与 ctx

```js

  ctx.on('student:judge', shape({ choice: 'enum:scam,normal' }), (socket, payload, actor) => {
    if (ctx.state.subPhase !== 'judge') return ctx.reject(socket, '已揭晓');

    ctx.data.setClass({ revealedAt: Date.now(), answer: 'scam', signals: ['催促', '链接'] });
```

ctx 的形状（签名以此为准，语义见规格 §6）：

```js
{
  stageId,
  on(event, schema, handler),           // schema 必填，无载荷写 shape({})；handler(socket, payload, actor)
                                        // actor = { role:'student', name } 或 { role:'teacher', name:null }
  reject(socket, message),              // 发 error:validation { event, message } 给该 socket；handler 外调用时 event 为 null
                                        // v0.8.3：学生端由外壳在横幅区显示 message 约 4 秒（§八），视图不用自己显示
  emitAll / emitTeachers / emitStudents(event, payload),
  emitToStudent(name, event, payload),  // 不在线静默
  emitToSocket(socket, event, payload), // 五个 emit 都校验 event 以 stage:<stageId>: 开头
  state: {                              // currentStage / subPhase 为 getter，每次读取都是当前值

  setSubPhase(x),
  data: {

    all(),                              // { [name]: record }

    setClass(patch),
    appendEvent(name, type, payload),   // 写 stage_events，不广播
  },
  log: { info, warn, error },           // 各为 (msg, extra?)，自动带 [stageId] 前缀
  ai: { configured, reason, chat(messages, opts) },  // v0.8.7：内核统一 AI 接口，见下文"调 AI"；与组件 cctx.ai 同一实例

```

内核处理一次事件的顺序：角色检查 → 是否当前阶段 → schema 校验 → handler。

事件规则（内核加载器强制）：

- 学生发起 `student:<动词>`，教师发起 `teacher:<动词>`，正则 `^(student|teacher):[a-z-]+$`——冒号后**只能是小写字母和连字符**，不能有数字、下划线、大写或第二个冒号（`student:step2`、`student:submit_1` 启动失败，写成 `student:step-two`）（v0.8.3 写明）；阶段广播 `stage:<stageId>:<名词>`
- 内核保留（阶段不得注册或发送）：`classroom:*`、`stage:change`、`stage:sub-phase`、`stage:data-update`、`stage:class-update`、`stage:my-data`、`student:join*`、`student:joined`、`student:left`、`student:switch-name`、`student:draft-set`（v0.9.0，由 `useDraft` 发）、`student:request-claim-release*`、`teacher:join*`、`teacher:advance*`、`teacher:admin-*`、`teacher:student-detail`、`teacher:get-student-detail`、`teacher:release-binding`、`teacher:reset-classroom`、`teacher:import-roster`、`teacher:clear-roster`、`error:*`（`classroom:*`、`stage:*`、`student:*`、`teacher:*`、`error:*` 由内核与阶段按本节规则使用）；组件前缀 `share:*`、`inbox:*`、`report:*`、`mirror:*`、`coach:*`、`sandbox:*`、`web-sim:*`，阶段不得使用（v0.6：`sandbox:*` 由代码沙盒组件使用；`web-sim:*` 保持保留，代码沙盒规格不使用）；v0.8.10：另加本课已启用的每个组件（含课程组件）的 `<cid>:*`（内核按已加载组件 id 生成，上面的内置表是缺省）
- 同一事件名可以在多个阶段注册（原语复用），内核只分发给当前阶段；某阶段注册过但不属于当前阶段的事件回 `error:validation { event, message:'stage inactive' }`；从未注册的事件名静默忽略
- `student:*` 只接受学生 socket，`teacher:*` 只接受教师 socket；内核自动 safeOn 包裹，handler 里 `throw` 也会变成 `error:validation`
- `data.set` / `data.setClass` 写入的记录**不得包含可识别学生身份的内容**（姓名、学号、按姓名索引的逐人数据等）：分享组件会把被帮助者的记录以匿名代号发给帮助者，记录本身若含身份信息即泄露（v0.5.1 增补）。例外（v0.8.1）：教师主动投屏写的**班级记录**可含被投屏学生的名字（如 free-text 的 `perClass.featured = { name, answers, at }`）——大屏本来就署名展示；学生记录（`data.set`）仍不得含身份信息
- `data.set`：内核按学生节流后向教师发 `stage:data-update { stageId, name, data }`（合并后的完整记录），并**不节流**地向本人单播 `stage:my-data { stageId, data }`（v0.9.1：`data.set(name, patch, { push })` 时这两条推送改发 `push(完整记录)` 的返回值——必须是普通对象，否则照发完整记录；存储、`get` / `all`、`join-ok` / `teacher:join-ok` / `teacher:get-student-detail`、导出与报告仍是完整记录。用于大字段不必每次重发的场合，如 code / data-analysis 的最终稿）；`data.setClass` 后向**全员**发 `stage:class-update { stageId, data }`

### shape() 规则（v0.8.3 写明，以 `kernel/server/schema.js` 为准）

`shape({ 键: 规则 })` 返回校验函数：载荷必须是对象（`undefined` 按 `{}`），**有没声明的键就拒绝**，声明了的键缺了就拒绝（`optional:` 除外）。失败时内核回 `error:validation`。**失败消息为中文，会经 `error:validation` 显示给学生**（§八；v0.8.5 起，此前是英文）：保留字段路径，如 `字段 choice 应为 scam、normal 之一，收到 "x"`、`字段 name 应为 string，收到 number`、`字段 text 长度应为 1-200，收到 0`、`缺少字段 answer`、`不认识的字段 extra`；校验嵌套对象时把外层路径作第二个参数传进去（`testsShape(p.tests, 'tests')` → `字段 tests.passed 应为 integer，收到 1.5`、`缺少字段 tests.cases[0].name`），不要自己拼前缀——仍是技术口吻，学生可能触发的校验（字数、范围、选项）宁可声明得宽一点，在 handler 里用 `ctx.reject(socket, '中文一句话')` 细查。

| 规则 | 通过条件 | 例 |
|---|---|---|
| `'string'` / `'string:a-b'` | 字符串；带范围时长度（UTF-16 计）在 a–b | `'string:1-200'` |
| `'integer'` / `'integer:a-b'` | 整数；带范围时值在 a–b | `'integer:0-100'` |
| `'number'` | 有限数（不带范围） | `'number'` |
| `'boolean'` | `true` / `false` | `'boolean'` |
| `'object'` | 普通对象（不是数组、不是 null）；**不查里面的字段** | `'object'` |
| `'enum:a,b,c'` | 字符串且是其中之一；**逗号**分隔 | `'enum:scam,normal'` |
| `'array:<规则>'` | 数组，每一项按冒号后的规则（可嵌套 `array:array:string`）；不限长度 | `'array:string'`、`'array:integer:0-9'` |
| `'optional:<规则>'` | 可缺省：值为 `undefined` 或 `null` 视为没写；**只能写在最外层的键上**（`array:optional:x` 启动时报错） | `'optional:string:1-50'` |

没有嵌套形状，也没有"或"：对象里面的字段写 `'object'` 后在 handler 里自己检查（例：`examples/anti-fraud/stages/05-intercept/server.js` 的 `checkWeights`）；数组长度、"两种写法二选一"同样在 handler 里查，不合法 `return ctx.reject(socket, '原因')`。

### 读别的段的数据（v0.8.3）

服务端 `ctx.data` 只读写**本段**的记录。某段要用学生在前面某段的结果时：

1. 学生页用 `useStudentStage('<那一段的 id>')` 读本人在那一段的记录（`myData`；join-ok 带回全部阶段的本人记录，刷新后也在）；
2. 发一个本段事件把需要的字段带上来（`send('student:run', { weights, threshold })`）；
3. 本段 `server.js` 按 `shape()` + handler 校验形状与取值，再写本段记录。

例：`examples/anti-fraud/stages/05-intercept`（学生页读第 4 段 `tune` 的最后一次设置，进入本段时自动发 `student:run`）。数据是学生自己发的，只能用于"用本人的结果做下一步"，不能当成防作弊的依据；要读**全班**在前一段的记录（如按上一段结果分组）现在做不到。服务端只读 API `ctx.data.of(stageId)` 待内核提供（内核待办）。

### 调 AI（v0.8.7，统一 AI 接口规格）

段里要让 AI 做点评、生成、判断、改写时，只用内核提供的 `ctx.ai`（组件里是 `cctx.ai`，同一个对象）。接口地址、模型、密钥只在工作台左边第 4 步"上课准备"填（写进 `.env` 的 `AI_BASE_URL` / `AI_MODEL` / `AI_API_KEY`，以及可选的备用接口 `AI_BASE_URL_2` / `AI_MODEL_2` / `AI_API_KEY_2`），超时、并发、排队、日志都由内核管。

```js
// stage.config.js：collect: { perStudent: { text: 'text', review: 'text', aiCount: 'integer' } }
const SYSTEM = '你是信息课助教。只点评学生这一句的思路，不给答案，不超过 60 字，不提学生名字。';   // 文件顶部中文常量

ctx.on('student:ask-review', shape({ text: 'string:1-300' }), async (socket, { text }, actor) => {
  const rec = ctx.data.get(actor.name) ?? {};
  if (!ctx.ai.configured) return ctx.data.set(actor.name, { text, review: null });   // 没配 AI：照常记录，不点评
  const used = rec.aiCount ?? 0;
  if (used >= 3) return ctx.reject(socket, '这一段的点评次数用完了');
  try {
    const payload = { who: ctx.anon.code(actor.name), text };                             // 不放真名
    const { content } = await ctx.ai.chat(
      [{ role: 'system', content: SYSTEM }, { role: 'user', content: JSON.stringify(payload) }],
      { caller: 'stage:<id>' },
    );
    ctx.data.set(actor.name, { text, review: content.replace(/\s+/g, ' ').slice(0, 80), aiCount: used + 1 });
  } catch (err) {
    if (err.reason === 'crowded') return ctx.reject(socket, '现在问的人太多，等一会再试');   // 排队满不计次（与 coach 一致）
    ctx.data.set(actor.name, { text, review: null, aiCount: used + 1 });                    // 其余失败也计次，防止刷
    ctx.reject(socket, 'AI 暂时没回应，先往下做');
  }
});
```

- `ctx.ai.configured`：主接口或备用接口任一组的地址与模型都填了即为 `true`；`ctx.ai.reason`：`null` 或 `'未配置'`。
- `await ctx.ai.chat(messages, { temperature = 0.2, maxTokens = 400, timeoutMs = 25000, caller })` → `{ content, ms, route }`（`content` 已去首尾空白；v0.8.14：返回值带 `route`，是这次实际回答的线路 1 / 2——工作台左边第 4 步"上课准备"填了备用接口时，主接口失败由内核自动改用备用，调用方式不变，`ms` 含失败那次）；`messages` 为 1–12 条 `{ role: 'system' | 'user' | 'assistant', content }`，合计 ≤ 20000 字（v0.8.11）；同一条线路不重试；填了备用接口时，可切换的失败会改用另一条再发一次（同样的 timeoutMs，最长约 2×）。失败抛 `AIError`，`err.reason` ∈ `not-configured` / `timeout` / `http-<状态码>` / `network` / `empty` / `crowded`（全平台同时在途 8 个、排队 20 个，再多立刻抛）/ `too-long`。
- 什么时候用：先想清楚没配 AI 时这段怎么上（降级文案 / 跳过这一步），`configured` 为 `false` 时不得报错中断。
- 怎么写：`SYSTEM` 是文件顶部的中文常量，写明身份、只做什么、不做什么、字数上限、不提学生名字；学生内容放 user 消息（JSON 文本）；`caller` 写 `'stage:<本段 id>'`（日志只记 caller、状态、耗时）。
- 不许：自己 `fetch` 任何模型接口；在课程代码里写地址 / 模型名 / 密钥（只在工作台左边第 4 步"上课准备"填）；把学生真名放进 messages（用 `ctx.anon.code(name)`）；把 AI 原文不加处理直接当成绩或判定（要截断与清理格式，长度上限自己定）。`check:lesson` 查课程代码里的接口地址、密钥与 `chat/completions`（§七）。
- 失败处理：`try / catch`，按 `err.reason` 给学生一句人话（`ctx.reject` 或写进记录），`crowded` 提示稍后再试；超时从拿到名额起算、排队时间不计，排队 + 请求最坏约 100 秒，客户端等待（如"点评中…"的兜底）要留余量；每人每段要有次数上限（自己在记录里计数，计数字段在 `collect.perStudent` 里声明；失败也计次、`crowded` 不计，与 coach 组件一致）。
- 数据：AI 的输入输出要进记录时写进 `collect.perStudent` 声明的字段（`text` / `object`），报告用 `summarize` 挑出来；不存完整 messages。

- `readOnly`（v0.5，仅学生 hook）：处于镜像（`MirrorProvider`）内时为 `true`，此时 `myData` / `classData` / `me` 来自镜像、`send` 为 no-op、`slice` 为切片 initial；非镜像时为 `false`。阶段无需据此适配（镜像外壳自带 inert 锁）
- `demo` / `setMyData`（v0.9.3，仅学生 hook；教师视图与学生页重排规格 §2.2）：教师端的**演示视图就是这一段的学生页**（教师演示模式，外壳用内核的 `DemoProvider` 包住 `StageStudentView`）。此时 `demo: true`、`readOnly: false`、`me = { name: '老师' }`、`options` 为**教师端完整 options（含保密项）**、`classData` 为教师端该段班级记录（`perClass`，揭晓 / 参考答案 / 下发都能看到）、`isLive` / `subPhase` 取教师端、`myData` 为**本地演示记录**、`setMyData(patch)` 写它（对象浅合并、函数 `(prev) => 新记录` 整条替换、`null` 删除；只在内存里，按课堂 + 段 id 记，换段保留、课堂重置清空）、`send` 为 no-op（`console.info` 一句，不发事件）、`useDraft` 退化为普通 state。其余情况 `demo: false`、没有 `setMyData`；镜像优先（镜像里 `demo` 为假）。原语的 Student 在 `demo` 下自己处理（本地提交、揭晓后本地判分）；**自写段不处理 `demo` 也行**——`send` 不发，相当于只读预览，`check:ui` 不要求
- `view`（v0.9.3，仅教师 hook）：外壳为本视图给的视图名——`'stats'`（统计视图）/ `'table'`（明细表）/ `'demo'`（旧式 `TeacherDemo.jsx`）；不在教师外壳里时 `null`。`TeacherStats.jsx` 在统计视图与明细表**都渲染**，可据此在统计视图放摘要区、在明细表放学生表；不区分时两种视图显示相同内容
- `me = { name, enteredStageAt, enteredStageIndex }`；`myData`：本人在本阶段的记录，无记录时 `undefined`；`classData` / `perClass`：本阶段班级记录，默认 `{}`；`roster = [{ name, connected, enteredStageAt, enteredStageIndex }]`；`perStudent = { [name]: record }`，默认 `{}`；`alerts`：仅 live 时求值，否则 `[]`，形状 `[{ id, text, names: [] }]`，`names` 为空的项不出现
- `send(event, payload)`：学生端只允许 `student:*`，教师端只允许 `teacher:*` 且不含内核保留事件（`teacher:advance` 等），违规抛错
- `advance({ force } = {})`（仅教师 hook）：推进到下一阶段的唯一途径，内核实现回看守卫与错误横幅。v0.7 起教师外壳操作条固定提供"进入下一段"（含门槛失败后的"继续 →" / "强制继续"），教师视图不再自放推进按钮
- `slice`：本阶段的客户端切片，来自可选的 `store.js`：

```js
// store.js（可选）
export default {
  student: { initial: { hint: null }, on: { 'stage:perceive:hint': (state, payload) => ({ ...state, hint: payload }) } },
  teacher: { initial: {}, on: {} },
};
```

处理函数返回**整个新切片**（替换，不合并）；`on` 的键只能是 `stage:<本阶段 id>:*`。切片只承载**临时**广播（动画触发、一次性提示）；需要刷新后仍在的班级数据必须放 `setClass`。内核在 `classroom:reset` 时把所有切片重置为 initial；`stage:change` 不清理。

规则：

- `Student.jsx` 在回看历史阶段时由内核按 `reviewInteractive` 决定是否加 inert 锁；组件内部不再判断
- 教师端三个视图（v0.9.3，教师视图与学生页重排规格 §2.3）：**演示视图**（该段 `Student.jsx`，教师演示模式；阶段目录自带旧式 `TeacherDemo.jsx` 时渲染它）、**统计视图**（`TeacherStats.jsx`，`view: 'stats'`，外壳套 table 模板、右侧组件 `teacherSidebar`）、**明细表**（`TeacherStats.jsx`，`view: 'table'`，通栏没有侧栏）；切换在操作条，当前段缺省演示视图、回看缺省统计视图。演示视图恒有（`hasDemo` 恒真）
- `TeacherActions.jsx`（v0.9.3，可缺省）：`export default function TeacherActions({ stageId })`，返回一组按钮（揭晓、取消展示、显示 / 公布参考答案……，可用 `useTeacherStage`）；外壳在**三个视图**的操作条左组、`Page.Actions` 之后渲染它；不放推进按钮（`check:ui` 查 `advance(`）
- `TeacherStats.jsx` 必须用内核的 `DataTable` 和 `AlertBar`；点击行渲染 `<DetailModal name tabs onClose />`，它挂载时自行取数、卸载时自行清理，阶段不处理 `teacher:student-detail`
- 界面只呈现数据与操作入口，不写教学提示文字（"平台不说废话"）；文案来源是阶段卡 A 栏
- 样式只用主题 token 与内核 `ui/`、`charts/`；响应式约束沿用内核
- 客户端没有 AI 接口（v0.8.7）：视图要 AI 结果时，发事件给本段 `server.js`，服务端 `ctx.ai.chat`（§三"调 AI"）后写 `ctx.data.set` 或 `emitToStudent`，视图读记录显示；视图里不写 `ctx.ai`，也不 `fetch` 外网（`check:lesson` 查）

### 学生输入自动保存（v0.9.0，学生输入自动保存规格）

学生在页面里输入的东西（文本框、输入框、勾选、滑块、未提交的作答与当前题号）**一律用 `useDraft`，不用裸 `useState`**：刷新、断线重连、关浏览器再进、换设备都不丢。

```js
import { useDraft } from '#kernel/client/index.js';
const [text, setText, { clear, restored }] = useDraft('text', '', { stageId: 'freeform' });
```

- `useDraft(field, initial, { stageId, local = true, server = true } = {})` → `[value, setValue, { clear, restored }]`；`setValue` 同 `useState`（可传函数）
- `field`：`/^[a-z][a-z0-9_-]{0,39}$/`（不合法抛错）；`value` 任意可 JSON 化的值，序列化后 ≤ 64 KB（超出只存本机，不发服务端，console.warn 一次）
- `stageId` 缺省取外壳给本视图的阶段；自写段建议照写本段 id；组件传 `'component:<id>'`
- 两层：本机 localStorage（键 `draft:<lessonId>:<classEpoch>:<name>:<stageId>:<field>`，防抖 300 ms）+ 服务端（`student:draft-set`，防抖 2 s，内核表 `drafts`）；卸载与 `pagehide` 时立即写本机并发一次服务端；断线期间只写本机，重连后与服务端不一致时补发
- 读取顺序：本机草稿 → 服务端草稿（`join-ok.myDrafts`）→ `initial`。**已提交的记录由视图自己算进 `initial` 或显示时回落**（常见写法：`useDraft('x', null)`，显示 `draft ?? myData.x`）
- `restored`：`'local' | 'server' | null`（本次值从哪层恢复，可用来显示"已恢复上次的内容"，可不用）
- `clear()`：删本机与服务端草稿，值回到 `initial`（没连上时本机记一个删除标记，连上后再删服务端那份，期间不会被服务端旧值找回）。**提交成功后（记录变了）调 `clear()`**；提交语义不变——草稿只是回填输入框，提交仍按本段事件发
- 教师端、镜像（`readOnly`）、没有 `me.name` 时退化为普通 `useState`（不读不写）
- `classroom:reset`（含离线期间被重置后再进的 `stale-session`）时内核清掉本课本机的 `draft:<lessonId>:` 与 `sandbox:<lessonId>:` 前缀；服务端 `drafts` 在教师重置与换课时整表清空
- 草稿**只给本人回填**：教师端、镜像、报告、导出一律不读；阶段服务端也读不到
- 低层工具 `draftKey({ lessonId, classEpoch, name, stageId, field })`、`readDraft(key)`（没有返回 `undefined`）、`writeDraft(key, value)`、`clearDraft(key)` 一般用不到
- `npm run check:ui` 对自写段 `stages/*/Student.jsx` 里有 `<textarea` / `<input` 却没用 `useDraft` 的给**提醒**（只打印，不影响退出码）；`npm run check:lesson` 对本课同样出**警告**（`draft-missing`）
- 服务端对未加入的连接、每人合计超过 1 MB 的草稿静默丢弃（不在学生屏弹红条）；客户端估算会超时不发

## 五、原语的使用方式（v0.8 重写，活动原语规格 §2）

原语是"带默认视图与处理器的阶段半成品"，放在 `primitives/<type>/`。阶段用 `stage.config.js` 的 `primitive: '<type>'` 选用、`options` 给参数。三种用法：

1. **直接用**：目录里只有 `STAGE.md` + `stage.config.js`（`{ id, label, primitive, options }`，≤ 30 行、无 JSX）；视图、事件、采集、门槛、提醒、报告条目、分享推荐全部来自原语
2. **覆盖视图**：保留原语的 server 与采集，在阶段目录放自己的 `Student.jsx`（或另两个视图），整体替换该视图
3. **不用**：`primitive: null`，全部自写（§一 的必需文件照旧）

合并与覆盖规则（服务端 `stage-loader` 合并出有效 config，内核其余部分不区分原语；客户端 `stageStores` 同规则合并客户端用得到的部分）：

| 项 | 原语提供 | 阶段可覆盖 | 规则 |
|---|---|---|---|
| `gate` | `defaults.gate(options)`（通常读 `options.gate`） | 是 | 阶段写了函数则只用阶段的 |
| `collect` | `defaults.collect` | 否 | 阶段写了启动失败；需要额外字段就不是这个原语 |
| `alerts` | `defaults.alerts(options)` | 追加 | 阶段的追加在原语之后；id 冲突启动失败 |
| `recommend` / `score` / `summarize` | `defaults.*(options)` | 是 | 同 gate |
| `onEnter` / `onLeave` / `onLateJoin` | `defaults.*(options)` | 追加 | 先原语后阶段（前一个 await 完再调后一个） |
| `subPhases` | `defaults.subPhases(options)` | 否 | 阶段写了启动失败 |
| `layout` | `primitive.config.layout` | 否 | 阶段写了启动失败；改布局 = 自写视图 |
| `sandbox`（v0.8，P2 用） | `defaults.sandbox(options)` | 否（原语提供时） | 原语提供时阶段写了启动失败；经 `classroom:state.stages[i].sandbox` 下发给前端 |
| `server.js` | 原语的 `register(ctx, options)` | 追加 | 先原语后阶段 `register(ctx)`；阶段可注册**新**事件，同名事件启动失败（`already registered`） |
| `Student.jsx` / `TeacherStats.jsx` / `TeacherActions.jsx`（v0.9.3） | 原语默认视图 / 操作条按钮 | 替换 | 阶段目录有同名文件则整体替换；`Student` / `TeacherStats` 两边都没有时放占位，`TeacherActions` 两边都没有就不渲染 |
| `TeacherDemo.jsx`（v0.9.3 起旧式） | 原语不提供 | — | 阶段目录有时演示视图渲染它（不渲染学生页）；没有时演示视图就是该段 `Student.jsx`（`hasDemo` 恒真） |
| `reviewInteractive`（v0.8.6） | `primitive.config.reviewInteractive`（布尔，可缺省） | 是 | 原语可给缺省，阶段没写时取原语的值、写了以阶段为准（教师可关）；code / data-analysis 缺省 `true`（回看可滚动、编辑、运行，不记录、不能上交），其余原语不写（缺省 false，回看加锁） |
| `components` / `label` | — | 是 | 照旧 |

`primitive.config.js` 形状：

```js
export default {
  type: 'vote',                 // 与目录名一致
  label: '投票',
  layout: 'focus',              // 学生视图的页面样式（有效 config 的 layout）
  options: validate,            // 校验函数：(options) => options，不合法抛错（shape({...}) 即可；联合类型自己包一层）
  requiresComponents: [],       // 可选：须在 lesson.config.components 里打开的组件，否则启动失败 阶段"<id>"：原语"<type>"需要打开组件"<id>"
  secretOptions: ['answer'],    // 可选：保密选项——classroom:state 里只有教师收到这些键，学生收到的 options 去掉它们
  reviewInteractive: true,      // 可选（v0.8.6）：回看缺省可交互（阶段写了以阶段为准）；不是布尔启动失败
  normalize(options, { stageDir, readFrom, readBinaryFrom }) { return options; },   // 可选：补缺省值、统一写法；可返回 Promise（v0.8.2，加载器 await）；
                                // readFrom(相对路径) 按 utf8 读、readBinaryFrom(相对路径)（v0.8.2）读成 Buffer，同 { from } 的路径限制、共用 256 KB 额度；
                                // 返回的 options 可带保留键 $server（对象，v0.8.2 仅服务端选项，见下）
  defaults: {                   // 每项是 (options) => 值 的工厂，值与 §二 同形；collect 也可直接写对象
    gate, collect, alerts, subPhases, recommend, score, summarize, onEnter, onLeave, onLateJoin,
  },
};
```

加载顺序：`options` 里（任意深度、含数组里）只有 `from` 一个键的对象按阶段目录读入为文本（解析后的真实路径——跟随软链——须在阶段根目录 `lesson.config.stagesDir` 内，课程根的 `.env`、`data/` 都不在其中，几段共用的文件放阶段根目录的子目录如 `stages/_shared/`；单文件与合计 ≤ 256 KB）→ `await normalize` → 摘出 `$server` → 校验 → 序列化 ≤ 256 KB → 合并。

仅服务端选项（v0.8.2，活动原语规格 §2.9）：`normalize` 返回的 options 里可以有保留键 `$server`（必须是对象，否则启动失败；`stage.config.js` 的 `options` 里写 `$server` 在 `normalize` 之前就报错"`$server` 由原语生成，不能在 stage.config.js 里写"）。加载器把它从下发给教师和学生的 `options`（有效 config 的 `options`、`classroom:state.stages[i].options`）里删掉；256 KB 序列化上限不计它；`options` 校验函数看不到它；`defaults.*` 工厂与原语 `register(ctx, options)` 拿到含 `$server` 的完整 options（`stages[i].serverOptions`）。客户端按 `classroom:state` 求值的工厂（`collect` / `alerts` / `gate` 等）拿不到 `$server`，只在服务端用的工厂（如 `sandbox`）才可以读它。原语加载、options 解析与合并（含 defaults 工厂调用）抛的错一律以 `阶段"<id>"：` 开头，如 `阶段"<id>"：原语"<type>"不存在`。`primitive` 为 null 的阶段写了 `options` 时加载器 console.warn 一句（不生效）。

保密选项：原语在 `secretOptions` 里列出的 options 键（vote 为 `answer`）只随教师的 `classroom:state`（`teacher:join-ok`、发往教师房间的广播）下发；连接时（角色未知；v0.9.1 起握手 `auth.teacherToken` 带有效教师 token 的连接直接收教师版，教师重连不再先收到学生版）、学生 `join-ok` 与发往其余 socket 的广播都去掉这些键。服务端的有效 config 与原语 `register(ctx, options)` 拿到的是完整 options。原语自己负责不经其它途径泄露（如 vote 提交回执不带 `correct`，揭晓时才把 `answer` 写进班级记录）。前端打包的 `stage.config.js` 不含 `options`，由内核构建插件 `kernel/build/strip-stage-options.js` 保证（`vite.config.js` 的 `kernelPlugins(aliases)`，vitest 复用）。插件只处理**本课阶段根目录下一层子目录里的** `stage.config.js`（按 `lesson.config.stagesDir` 解析出的实际目录，不看路径字面），规则如下，不满足的一律**构建失败**并写明文件与改写要求：

- 必须有 `export default` 声明；默认导出必须是**对象字面量**，或指向同文件顶层 **`const` 对象字面量**的标识符。`export { cfg as default }`、`export default make()`、import 进来的对象都不行
- 默认导出对象的顶层不得有展开（`...base`）和计算属性名（`[key]: …`）
- 顶层 `options` 属性从源码文本里删掉（打包文件里不留字面量）；再包一层运行时兜底 `delete`
- 纵深防御：插件记下被删 `options` 里 ≥ 8 字符的字符串（标识符 / 枚举样的串除外），构建结束时扫描输出文件，发现即构建失败——例如同一段文字又经具名导出被视图 import

所以**前端代码（视图、`store.js`、组件）不得从 `stage.config.js` 读 `options`**，`options` 里的文字也不要再经别的导出给视图用；前端所有 options 都来自 `classroom:state`。服务端直接 import，不受影响。

原语的默认视图用 `useStudentStage()` / `useTeacherStage()`（不写 id，§四）取数，用返回的 `options` 渲染，不读 `perClass` 兜底题目。声明式门槛（`options.gate`）与统一统计骨架在 `primitives/_shared/`（`gate.js`、`StatsPage.jsx`），只给原语用。已有原语与用法见各自的 `primitives/<type>/README.md`，一期清单见活动原语规格 §3。

## 六、阶段生命周期与 enteredStageAt

教师推进时内核依次：`gate`（除非 force）→ `await onLeave(ctx)`（旧阶段，超时 2 s，异常只记日志）→ `currentIndex++`、`subPhase = null`、对**在线**学生写 `enteredStageAt = now`、`enteredStageIndex = currentIndex`，离线学生两项置 `null` → 持久化 → 广播 `stage:change` → fire-and-forget `onEnter(ctx)`（新阶段）。

学生加入或重连（任何阶段）：若 `enteredStageIndex !== currentIndex` 则写 `enteredStageAt = now`、`enteredStageIndex = currentIndex` 并记 `firstEntry = true`，否则 `firstEntry = false`；回 join-ok；若当前阶段（非 prelogin / curtain）定义了 `onLateJoin`，调用 `onLateJoin(student, ctx, { firstEntry })`。两项都持久化在 students 表，重启后不丢。
