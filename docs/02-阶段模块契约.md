## 三、server.js 与 ctx

```js
import { shape } from '#kernel/server/schema.js';

export function register(ctx) {
  ctx.on('student:judge', shape({ choice: 'enum:scam,normal' }), (socket, payload, actor) => {
    if (ctx.state.subPhase !== 'judge') return ctx.reject(socket, '已揭晓');
    const me = ctx.state.student(actor.name);
    ctx.data.set(actor.name, { judgment: payload.choice, elapsedMs: Date.now() - me.enteredStageAt });
    // 不需要手动通知教师：data.set 后内核自动发 stage:data-update 给教师、stage:my-data 给本人
  });

  ctx.on('teacher:reveal', shape({}), (socket) => {
    ctx.setSubPhase('reveal');
    ctx.data.setClass({ revealedAt: Date.now(), answer: 'scam', signals: ['催促', '链接'] });
    // setClass 后内核向全员发 stage:class-update；学生刷新后也能从 join-ok 的 classData 拿回
  });
}
```

ctx 的形状（签名以此为准，语义见规格 §6）：

```js
{
  stageId,
  on(event, schema, handler),           // schema 必填，无载荷写 shape({})；handler(socket, payload, actor)
                                        // actor = { role:'student', name } 或 { role:'teacher', name:null }
  reject(socket, message),              // 发 error:validation { event, message } 给该 socket；handler 外调用时 event 为 null
                                        // v0.8.3：学生端由外壳在横幅区显示 message 约 4 秒（§八），视图不用自己显示
  emitAll / emitTeachers / emitStudents(event, payload),
  emitToStudent(name, event, payload),  // 不在线静默
  emitToSocket(socket, event, payload), // 五个 emit 都校验 event 以 stage:<stageId>: 开头
  state: {                              // currentStage / subPhase 为 getter，每次读取都是当前值
    currentStage, subPhase,
    students(),                         // 全部 [{ name, connected, enteredStageAt, enteredStageIndex }]
    connected(),                        // 仅在线
    student(name),                      // 单个或 undefined
  },
  setSubPhase(x),
  data: {
    get(name),                          // record 或 undefined
    set(name, patch),                   // 浅合并 + updatedAt
    all(),                              // { [name]: record }
    getClass(),                         // 无记录时返回 {}
    setClass(patch),
    appendEvent(name, type, payload),   // 写 stage_events，不广播
  },
  log: { info, warn, error },           // 各为 (msg, extra?)，自动带 [stageId] 前缀
}
```

内核处理一次事件的顺序：角色检查 → 是否当前阶段 → schema 校验 → handler。

事件规则（内核加载器强制）：

- 学生发起 `student:<动词>`，教师发起 `teacher:<动词>`，正则 `^(student|teacher):[a-z-]+$`——冒号后**只能是小写字母和连字符**，不能有数字、下划线、大写或第二个冒号（`student:step2`、`student:submit_1` 启动失败，写成 `student:step-two`）（v0.8.3 写明）；阶段广播 `stage:<stageId>:<名词>`
- 内核保留（阶段不得注册或发送）：`classroom:*`、`stage:change`、`stage:sub-phase`、`stage:data-update`、`stage:class-update`、`stage:my-data`、`student:join*`、`student:joined`、`student:left`、`student:switch-name`、`student:request-claim-release*`、`teacher:join*`、`teacher:advance*`、`teacher:admin-*`、`teacher:student-detail`、`teacher:get-student-detail`、`teacher:release-binding`、`teacher:reset-classroom`、`teacher:import-roster`、`teacher:clear-roster`、`error:*`（`classroom:*`、`stage:*`、`student:*`、`teacher:*`、`error:*` 由内核与阶段按本节规则使用）；组件前缀 `share:*`、`inbox:*`、`report:*`、`mirror:*`、`coach:*`、`sandbox:*`、`web-sim:*`，阶段不得使用（v0.6：`sandbox:*` 由代码沙盒组件使用；`web-sim:*` 保持保留，代码沙盒规格不使用）
- 同一事件名可以在多个阶段注册（原语复用），内核只分发给当前阶段；某阶段注册过但不属于当前阶段的事件回 `error:validation { event, message:'stage inactive' }`；从未注册的事件名静默忽略
- `student:*` 只接受学生 socket，`teacher:*` 只接受教师 socket；内核自动 safeOn 包裹，handler 里 `throw` 也会变成 `error:validation`
- `data.set` / `data.setClass` 写入的记录**不得包含可识别学生身份的内容**（姓名、学号、按姓名索引的逐人数据等）：分享组件会把被帮助者的记录以匿名代号发给帮助者，记录本身若含身份信息即泄露（v0.5.1 增补）。例外（v0.8.1）：教师主动投屏写的**班级记录**可含被投屏学生的名字（如 free-text 的 `perClass.featured = { name, answers, at }`）——大屏本来就署名展示；学生记录（`data.set`）仍不得含身份信息
- `data.set`：内核按学生节流后向教师发 `stage:data-update { stageId, name, data }`（合并后的完整记录），并**不节流**地向本人单播 `stage:my-data { stageId, data }`；`data.setClass` 后向**全员**发 `stage:class-update { stageId, data }`

### shape() 规则（v0.8.3 写明，以 `kernel/server/schema.js` 为准）

`shape({ 键: 规则 })` 返回校验函数：载荷必须是对象（`undefined` 按 `{}`），**有没声明的键就拒绝**，声明了的键缺了就拒绝（`optional:` 除外）。失败时内核回 `error:validation`，消息是英文技术文字（如 `choice: must be one of scam,normal`）并会显示给学生（§八）——学生可能触发的校验（字数、范围、选项）宁可声明得宽一点，在 handler 里用 `ctx.reject(socket, '中文一句话')` 细查。

| 规则 | 通过条件 | 例 |
|---|---|---|
| `'string'` / `'string:a-b'` | 字符串；带范围时长度（UTF-16 计）在 a–b | `'string:1-200'` |
| `'integer'` / `'integer:a-b'` | 整数；带范围时值在 a–b | `'integer:0-100'` |
| `'number'` | 有限数（不带范围） | `'number'` |
| `'boolean'` | `true` / `false` | `'boolean'` |
| `'object'` | 普通对象（不是数组、不是 null）；**不查里面的字段** | `'object'` |
| `'enum:a,b,c'` | 字符串且是其中之一；**逗号**分隔 | `'enum:scam,normal'` |
| `'array:<规则>'` | 数组，每一项按冒号后的规则（可嵌套 `array:array:string`）；不限长度 | `'array:string'`、`'array:integer:0-9'` |
| `'optional:<规则>'` | 可缺省：值为 `undefined` 或 `null` 视为没写；**只能写在最外层的键上**（`array:optional:x` 启动时报错） | `'optional:string:1-50'` |

没有嵌套形状，也没有"或"：对象里面的字段写 `'object'` 后在 handler 里自己检查（例：`examples/anti-fraud/stages/05-intercept/server.js` 的 `checkWeights`）；数组长度、"两种写法二选一"同样在 handler 里查，不合法 `return ctx.reject(socket, '原因')`。

### 读别的段的数据（v0.8.3）

服务端 `ctx.data` 只读写**本段**的记录。某段要用学生在前面某段的结果时：

1. 学生页用 `useStudentStage('<那一段的 id>')` 读本人在那一段的记录（`myData`；join-ok 带回全部阶段的本人记录，刷新后也在）；
2. 发一个本段事件把需要的字段带上来（`send('student:run', { weights, threshold })`）；
3. 本段 `server.js` 按 `shape()` + handler 校验形状与取值，再写本段记录。

例：`examples/anti-fraud/stages/05-intercept`（学生页读第 4 段 `tune` 的最后一次设置，进入本段时自动发 `student:run`）。数据是学生自己发的，只能用于"用本人的结果做下一步"，不能当成防作弊的依据；要读**全班**在前一段的记录（如按上一段结果分组）现在做不到。服务端只读 API `ctx.data.of(stageId)` 待内核提供（内核待办）。

## 四、视图与 store

三个视图只从内核 hooks 取数据，不自建 socket：

```js
import { useStudentStage, useTeacherStage, DataTable, AlertBar } from '#kernel/client/index.js';
// Student.jsx
const { stage, subPhase, isLive, me, myData, classData, send, slice, readOnly, options } = useStudentStage('perceive');
// TeacherDemo.jsx / TeacherStats.jsx
const { stage, subPhase, isLive, roster, perStudent, perClass, send, slice, alerts, advance, options } = useTeacherStage('perceive');
```

- v0.8：阶段 id 可缺省（`useStudentStage()` / `useTeacherStage()`）：取外壳为本视图提供的阶段（渲染 `Student` / `TeacherDemo` / `TeacherStats` 时外壳已提供）。原语的默认视图不知道自己被哪个阶段使用，必须这样写；阶段自写视图照旧写 id
- v0.8：`options`：本阶段 `classroom:state.stages[i].options`（加载时校验过的原语参数），非原语阶段为 `null`；教师 hook 取教师端的 classroom:state，学生 hook 取本端（镜像在教师端渲染时取教师端）。**学生端的 `options` 不含原语的保密选项**（§五），学生视图不得依赖它们，需要时从 `classData` 读原语在合适时机写入的值（如 vote 揭晓时写的 `answer`）。`stage` 为**有效 config**：原语阶段已合并原语的 `layout` / `collect` / `subPhases` / `alerts` / `gate` / `recommend` / `score` / `summarize`（§五），`stage.options` 与 `options` 同值
- v0.8：原语阶段的 `sandbox` 配置来自服务端：原语 `defaults.sandbox(options)` 的结果经 `classroom:state.stages[i].sandbox` 下发（师生同一份，不得含保密选项的内容）；前端打包的 `stage.config.js` 没有 `options`，算不出它。非原语阶段没有这个字段，照旧读自己 `stage.config.js` 的 `sandbox`。sandbox 组件客户端已接（P2）：内核客户端把 `stages[i].sandbox` 并入原语阶段的有效 config，组件照旧读 `stage.sandbox`

- `stage`：本阶段的 `stage.config` 对象；`isLive`：本阶段是否为当前阶段；`subPhase`：非 live 时为 `null`
- `readOnly`（v0.5，仅学生 hook）：处于镜像（`MirrorProvider`）内时为 `true`，此时 `myData` / `classData` / `me` 来自镜像、`send` 为 no-op、`slice` 为切片 initial；非镜像时为 `false`。阶段无需据此适配（镜像外壳自带 inert 锁）
- `me = { name, enteredStageAt, enteredStageIndex }`；`myData`：本人在本阶段的记录，无记录时 `undefined`；`classData` / `perClass`：本阶段班级记录，默认 `{}`；`roster = [{ name, connected, enteredStageAt, enteredStageIndex }]`；`perStudent = { [name]: record }`，默认 `{}`；`alerts`：仅 live 时求值，否则 `[]`，形状 `[{ id, text, names: [] }]`，`names` 为空的项不出现
- `send(event, payload)`：学生端只允许 `student:*`，教师端只允许 `teacher:*` 且不含内核保留事件（`teacher:advance` 等），违规抛错
- `advance({ force } = {})`（仅教师 hook）：推进到下一阶段的唯一途径，内核实现回看守卫与错误横幅。v0.7 起教师外壳操作条固定提供"进入下一段"（含门槛失败后的"继续 →" / "强制继续"），教师视图不再自放推进按钮
- `slice`：本阶段的客户端切片，来自可选的 `store.js`：

```js
// store.js（可选）
export default {
  student: { initial: { hint: null }, on: { 'stage:perceive:hint': (state, payload) => ({ ...state, hint: payload }) } },
  teacher: { initial: {}, on: {} },
};
```

处理函数返回**整个新切片**（替换，不合并）；`on` 的键只能是 `stage:<本阶段 id>:*`。切片只承载**临时**广播（动画触发、一次性提示）；需要刷新后仍在的班级数据必须放 `setClass`。内核在 `classroom:reset` 时把所有切片重置为 initial；`stage:change` 不清理。

规则：

- `Student.jsx` 在回看历史阶段时由内核按 `reviewInteractive` 决定是否加 inert 锁；组件内部不再判断
- `TeacherDemo.jsx` 缺省时内核只显统计视图并隐藏切换按钮
- `TeacherStats.jsx` 必须用内核的 `DataTable` 和 `AlertBar`；点击行渲染 `<DetailModal name tabs onClose />`，它挂载时自行取数、卸载时自行清理，阶段不处理 `teacher:student-detail`
- 界面只呈现数据与操作入口，不写教学提示文字（"平台不说废话"）；文案来源是阶段卡 A 栏
- 样式只用主题 token 与内核 `ui/`、`charts/`；响应式约束沿用内核

## 五、原语的使用方式（v0.8 重写，活动原语规格 §2）

原语是"带默认视图与处理器的阶段半成品"，放在 `primitives/<type>/`。阶段用 `stage.config.js` 的 `primitive: '<type>'` 选用、`options` 给参数。三种用法：

1. **直接用**：目录里只有 `STAGE.md` + `stage.config.js`（`{ id, label, primitive, options }`，≤ 30 行、无 JSX）；视图、事件、采集、门槛、提醒、报告条目、分享推荐全部来自原语
2. **覆盖视图**：保留原语的 server 与采集，在阶段目录放自己的 `Student.jsx`（或另两个视图），整体替换该视图
3. **不用**：`primitive: null`，全部自写（§一 的必需文件照旧）

合并与覆盖规则（服务端 `stage-loader` 合并出有效 config，内核其余部分不区分原语；客户端 `stageStores` 同规则合并客户端用得到的部分）：

| 项 | 原语提供 | 阶段可覆盖 | 规则 |
|---|---|---|---|
| `gate` | `defaults.gate(options)`（通常读 `options.gate`） | 是 | 阶段写了函数则只用阶段的 |
| `collect` | `defaults.collect` | 否 | 阶段写了启动失败；需要额外字段就不是这个原语 |
| `alerts` | `defaults.alerts(options)` | 追加 | 阶段的追加在原语之后；id 冲突启动失败 |
| `recommend` / `score` / `summarize` | `defaults.*(options)` | 是 | 同 gate |
| `onEnter` / `onLeave` / `onLateJoin` | `defaults.*(options)` | 追加 | 先原语后阶段（前一个 await 完再调后一个） |
| `subPhases` | `defaults.subPhases(options)` | 否 | 阶段写了启动失败 |
| `layout` | `primitive.config.layout` | 否 | 阶段写了启动失败；改布局 = 自写视图 |
| `sandbox`（v0.8，P2 用） | `defaults.sandbox(options)` | 否（原语提供时） | 原语提供时阶段写了启动失败；经 `classroom:state.stages[i].sandbox` 下发给前端 |
| `server.js` | 原语的 `register(ctx, options)` | 追加 | 先原语后阶段 `register(ctx)`；阶段可注册**新**事件，同名事件启动失败（`already registered`） |
| `Student.jsx` / `TeacherDemo.jsx` / `TeacherStats.jsx` | 原语默认视图 | 替换 | 阶段目录有同名文件则整体替换该视图；两边都没有时放占位（TeacherDemo 缺省即 `hasDemo=false`） |
| `components` / `reviewInteractive` / `label` | — | 是 | 照旧 |

`primitive.config.js` 形状：

```js
export default {
  type: 'vote',                 // 与目录名一致
  label: '投票',
  layout: 'focus',              // 学生视图的页面样式（有效 config 的 layout）
  options: validate,            // 校验函数：(options) => options，不合法抛错（shape({...}) 即可；联合类型自己包一层）
  requiresComponents: [],       // 可选：须在 lesson.config.components 里打开的组件，否则启动失败 阶段"<id>"：原语"<type>"需要打开组件"<id>"
  secretOptions: ['answer'],    // 可选：保密选项——classroom:state 里只有教师收到这些键，学生收到的 options 去掉它们
  normalize(options, { stageDir, readFrom, readBinaryFrom }) { return options; },   // 可选：补缺省值、统一写法；可返回 Promise（v0.8.2，加载器 await）；
                                // readFrom(相对路径) 按 utf8 读、readBinaryFrom(相对路径)（v0.8.2）读成 Buffer，同 { from } 的路径限制、共用 256 KB 额度；
                                // 返回的 options 可带保留键 $server（对象，v0.8.2 仅服务端选项，见下）
  defaults: {                   // 每项是 (options) => 值 的工厂，值与 §二 同形；collect 也可直接写对象
    gate, collect, alerts, subPhases, recommend, score, summarize, onEnter, onLeave, onLateJoin,
  },
};
```

加载顺序：`options` 里（任意深度、含数组里）只有 `from` 一个键的对象按阶段目录读入为文本（解析后的真实路径——跟随软链——须在阶段根目录 `lesson.config.stagesDir` 内，课程根的 `.env`、`data/` 都不在其中，几段共用的文件放阶段根目录的子目录如 `stages/_shared/`；单文件与合计 ≤ 256 KB）→ `await normalize` → 摘出 `$server` → 校验 → 序列化 ≤ 256 KB → 合并。

仅服务端选项（v0.8.2，活动原语规格 §2.9）：`normalize` 返回的 options 里可以有保留键 `$server`（必须是对象，否则启动失败；`stage.config.js` 的 `options` 里写 `$server` 在 `normalize` 之前就报错"`$server` 由原语生成，不能在 stage.config.js 里写"）。加载器把它从下发给教师和学生的 `options`（有效 config 的 `options`、`classroom:state.stages[i].options`）里删掉；256 KB 序列化上限不计它；`options` 校验函数看不到它；`defaults.*` 工厂与原语 `register(ctx, options)` 拿到含 `$server` 的完整 options（`stages[i].serverOptions`）。客户端按 `classroom:state` 求值的工厂（`collect` / `alerts` / `gate` 等）拿不到 `$server`，只在服务端用的工厂（如 `sandbox`）才可以读它。原语加载、options 解析与合并（含 defaults 工厂调用）抛的错一律以 `阶段"<id>"：` 开头，如 `阶段"<id>"：原语"<type>"不存在`。`primitive` 为 null 的阶段写了 `options` 时加载器 console.warn 一句（不生效）。

保密选项：原语在 `secretOptions` 里列出的 options 键（vote 为 `answer`）只随教师的 `classroom:state`（`teacher:join-ok`、发往教师房间的广播）下发；连接时（角色未知）、学生 `join-ok` 与发往其余 socket 的广播都去掉这些键。服务端的有效 config 与原语 `register(ctx, options)` 拿到的是完整 options。原语自己负责不经其它途径泄露（如 vote 提交回执不带 `correct`，揭晓时才把 `answer` 写进班级记录）。前端打包的 `stage.config.js` 不含 `options`，由内核构建插件 `kernel/build/strip-stage-options.js` 保证（`vite.config.js` 的 `kernelPlugins(aliases)`，vitest 复用）。插件只处理**本课阶段根目录下一层子目录里的** `stage.config.js`（按 `lesson.config.stagesDir` 解析出的实际目录，不看路径字面），规则如下，不满足的一律**构建失败**并写明文件与改写要求：

- 必须有 `export default` 声明；默认导出必须是**对象字面量**，或指向同文件顶层 **`const` 对象字面量**的标识符。`export { cfg as default }`、`export default make()`、import 进来的对象都不行
- 默认导出对象的顶层不得有展开（`...base`）和计算属性名（`[key]: …`）
- 顶层 `options` 属性从源码文本里删掉（打包文件里不留字面量）；再包一层运行时兜底 `delete`
- 纵深防御：插件记下被删 `options` 里 ≥ 8 字符的字符串（标识符 / 枚举样的串除外），构建结束时扫描输出文件，发现即构建失败——例如同一段文字又经具名导出被视图 import

所以**前端代码（视图、`store.js`、组件）不得从 `stage.config.js` 读 `options`**，`options` 里的文字也不要再经别的导出给视图用；前端所有 options 都来自 `classroom:state`。服务端直接 import，不受影响。

原语的默认视图用 `useStudentStage()` / `useTeacherStage()`（不写 id，§四）取数，用返回的 `options` 渲染，不读 `perClass` 兜底题目。声明式门槛（`options.gate`）与统一统计骨架在 `primitives/_shared/`（`gate.js`、`StatsPage.jsx`），只给原语用。已有原语与用法见各自的 `primitives/<type>/README.md`，一期清单见活动原语规格 §3。

## 六、阶段生命周期与 enteredStageAt

教师推进时内核依次：`gate`（除非 force）→ `await onLeave(ctx)`（旧阶段，超时 2 s，异常只记日志）→ `currentIndex++`、`subPhase = null`、对**在线**学生写 `enteredStageAt = now`、`enteredStageIndex = currentIndex`，离线学生两项置 `null` → 持久化 → 广播 `stage:change` → fire-and-forget `onEnter(ctx)`（新阶段）。

学生加入或重连（任何阶段）：若 `enteredStageIndex !== currentIndex` 则写 `enteredStageAt = now`、`enteredStageIndex = currentIndex` 并记 `firstEntry = true`，否则 `firstEntry = false`；回 join-ok；若当前阶段（非 prelogin / curtain）定义了 `onLateJoin`，调用 `onLateJoin(student, ctx, { firstEntry })`。两项都持久化在 students 表，重启后不丢。
