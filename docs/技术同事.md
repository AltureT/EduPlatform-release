# 给技术同事

> 读者：帮老师装平台、排查问题的技术同事，以及开发者。老师日常只用工作台（双击 `班迹工作台.command` / `班迹工作台.bat`），不需要读这一页。
> 做课的 AI 入口与契约见 `docs/00-框架地图.md`；本页是原 README"附：开发者命令""给 AI 的三条命令"与手动换国内源安装的搬家。

## 一、第一次打开时的系统提示与安装失败

- Mac 第一次双击提示"无法打开"或"无法验证开发者"：先点"完成"（或"取消"）关掉提示，打开"系统设置 → 隐私与安全性"，往下找到关于"班迹工作台.command"的提示，点"仍要打开"，再输入电脑密码确认。之后就可以直接双击了。（macOS 15 起，右键"打开"的老办法已经不管用。）
- Windows 第一次双击出现蓝色的"Windows 已保护你的电脑"：点"更多信息"，再点"仍要运行"。
- 第一次双击会自动安装平台需要的组件（要联网，几分钟）。装不上时窗口里会显示"换国内源再试一次…"，自动换国内源再装一次；还不行就用下面"手动换国内源安装"的命令，或者把另一台装好的平台文件夹里的整个 `node_modules` 拷过来再双击。
- 窗口里问"要不要自动下载 Node.js"时按回车（约 50 MB，装在平台文件夹的 `vendor/node/`，不改动系统）；输入 n 就要自己装好 22 或 24 版再双击。
- 浏览器没自动打开工作台：把窗口里显示的地址（形如 `http://127.0.0.1:3900/?t=…`）复制到浏览器。每次双击都会生成新地址，旧地址提示"链接已失效"时回窗口复制新的。
- Linux 教师机：在平台文件夹的终端里运行 `npm run manage` 打开工作台（等同于双击入口）。1024 以下的端口（包括 80）要管理员权限，到工作台第 4 步"上课准备"把端口改成 3001 或 8080，保存后重启平台。

## 二、上课时的网络与端口

- 学生连不上：平板和教师电脑要在同一个 WiFi（有些学校的访客网络彼此不通）。Mac 弹出"是否允许接受网络连接"点"允许"；Windows 第一次启动平台时询问是否允许 Node.js 访问网络，把"专用网络"和"公用网络"**两项都勾上**——学校 WiFi 常被识别为"公用网络"。当时只勾了一项的，到"Windows 安全中心 → 防火墙和网络保护 → 允许应用通过防火墙"给 Node.js 两项都勾上。在教师电脑上打开学生地址也打不开，说明平台没启动成功，看工作台页面上方的出错说明。
- 端口被占用：工作台会查出是谁占着端口并给出按钮——之前没关掉的本平台可以"停止它并启动"（只结束判定为本平台文件夹里的平台，正在连它的学生刷新即可）；别的程序占着就点"改用 ……"换端口，或关掉那个程序后点"已关掉，重试"。
- 双击提示"已经有一个工作台窗口在运行"：同一个平台文件夹同时只能开一个工作台。旧窗口没在上课时会被自动替换；正在上课、更新平台、恢复 / 重置数据或下载运行时则不替换，找到那个窗口继续用。确定没有别的工作台窗口（例如刚死机重启过）还提示，删除平台文件夹里的 `.manage.lock` 再双击。不想自动替换的，用 `npm run manage -- --no-replace` 启动。
- 关掉那个窗口 = 关掉工作台和平台。上课期间不要关（可以最小化）；不小心关了，重新双击，在第 5 步点"启动平台"即可，数据都还在。课中重启平台学生进度保留，只有改了课程本身（例如增删了环节）才从头开始。

## 三、更新与退回

- 更新失败会自动恢复，备份在平台文件夹的 `backups/updates`。想退回旧版本：关掉工作台窗口，把 `backups/updates/before-v<旧版本>-<时间>/` 里的文件按原位置拷回平台文件夹覆盖，或者重新解压旧版本的发布包覆盖平台文件夹。
- 更新中途被打断（关窗口、断电）时，下次打开工作台会自动恢复到更新前；工作台打不开时，在平台文件夹里运行 `node scripts/update-platform.mjs --recover`。
- 数据存在 `data/lessons/<课程 id>.sqlite`，备份在 `backups/lessons/<课程 id>/`；删除的课移到 `backups/deleted-lessons/`，需要时可以挪回 `lessons/`。

## 四、开发者命令

以下命令在平台文件夹的终端里运行，教师日常不需要。

开发者也可以不用发布包，直接 `git clone` 平台的开发仓库：仓库里的 `template/` 就是平台文件夹（命令都在 `template/` 里执行）。在仓库根运行 `npm run pack:release`，生成发给教师的发布包 `release/班迹-v<版本号>.zip`（需要系统有 `zip`）；`npm run publish:release` 再把它发到公开发布仓库 https://github.com/AltureT/EduPlatform-release 并同步推到 Gitee 镜像 https://gitee.com/alture/EduPlatform-release （仓库内容 = 解压后的平台文件夹，Releases 里的 zip 叫 `EduPlatform-v<版本号>.zip`；Gitee 的 Release 附件要环境变量 `GITEE_TOKEN`，没有时脚本打印手动上传地址；`--no-gitee` 只发 GitHub）。Python 运行时整包：`npm run pack:runtime` 把 `template/vendor/pyodide` 打成 `release/EduPlatform-runtime-v<版本>.zip`，`npm run publish:release -- --runtime-only` 把它挂到两边的 `runtime-v<版本>` Release（`--runtime` 在发新版本时顺带做）。Gitee 推送失败时退出码 2，网络恢复后重跑 `publish:release`（内容没变）会补推 Gitee 并补建 Gitee Release；但如果 tag 已经推上 Gitee、只是建 Release 或传附件失败（或当时没设 `GITEE_TOKEN`），重跑不会再建，要按脚本打印的地址到 Gitee 网页手动上传。工作台导入运行时整包时，内核文件、包闭包的 `.whl` 与两份 lock 都按固定的 sha256 核对，`.gz` 按原文件重新生成；`wheels/` 下的 PyPI 轮子（Flask 等）只按整包自带的 manifest 校验。

`vendor/node/` 是双击入口自动下载的便携 Node（没有系统 Node 或版本低于 22 时，问过教师再装；有它就优先用它）；删掉 `vendor/node/` 就回到系统 Node。系统里没有 Node 时，终端里的命令前加 `PATH="$PWD/vendor/node/bin:$PATH"`（Windows 命令提示符先 `set "PATH=%CD%\vendor\node;%PATH%"`）。

```
npm install              # 安装依赖（双击入口会自动做；失败时会换国内源再试一次）
npm run manage           # 打开工作台（等同于双击入口；Linux 教师机用这个）
npm run dev              # 开发模式：Vite 热更新，代理到 3001 端口的服务端
npm run server           # 只启动服务端（读 .env）
npm run build            # 构建前端到 dist/
npm test                 # 全部自动测试
npm run fetch:pyodide    # 下载 Python 运行时（同工作台里的下载按钮）：vendor/ 里的整包 → RUNTIME_ZIP_URL → Gitee 整包 → GitHub 整包 → 逐文件
npm run fetch:pyodide -- --sources   # 只列出下载来源的顺序，不下载
npm run gen:ai-entry     # 改了 scripts/lib/ai-entry.js 后重新生成各 AI 工具的入口文件（CLAUDE.md、AGENTS.md、.cursor/ 等十个，正文同源；--check 只比对）
```

发布包的 `版本.json` 带 `protected`（平台文件 → sha256，范围见 `scripts/lib/platform-files.js`）；`check:lesson` 与工作台"平台"页的"平台版本"一节据它报"平台文件被改过"。开发仓库里没有 `版本.json`，不做这项检查。

- 配置保存在 `.env`（工作台自动生成与维护，不进版本库）；可选项见 `.env.example`。
- 换课程：工作台顶上的"当前课程"下拉框（只列 `lessons/` 下的课），会写入 `.env` 的 `LESSON_CONFIG`；项目根目录的 `lesson.config.js` 留给开发调试用（它是当前课程时下拉框里显示"我的课程（自定义）"）。新装时 `LESSON_CONFIG` 取 `lessons/` 下第一门课，没有就留空（= 还没有课程）；`examples/` 只是给 AI 照抄的范本，工作台不列它。
- 平台输出记录在 `data/logs/server.log`（超过 5 MB 自动换新文件，旧的保留一份为 `server.log.1`）。
- `MANAGE_PORT=3920 npm run manage`：工作台改从 3920 起找空闲端口（默认 3900–3909），测试与本地验证用。
- "停止它并启动"如何判定"本平台"：占端口进程命令行里的第一个非选项参数就是脚本（其后不能再有参数）；脚本是绝对路径时必须正好是本平台文件夹下的 `kernel/server/index.js`，是相对路径时按进程工作目录解析后等于它（Mac / Linux 用 `lsof` 与 `ps` / `/proc` 查）。Windows 用一次 PowerShell（`Get-NetTCPConnection` + `Get-CimInstance Win32_Process`）查，拿不到别的进程的工作目录，只认绝对路径（工作台自己启动平台时就用绝对路径）；用 `npm run server` 启动的旧平台在 Windows 上会显示为"被「node.exe」占用"。

## 五、手动换国内源安装

自动换源也装不上时，在平台文件夹的终端里运行：

```
# Mac / Linux：
npm_config_registry=https://registry.npmmirror.com npm_config_better_sqlite3_binary_host_mirror=https://registry.npmmirror.com/-/binary/better-sqlite3 npm install

# Windows（命令提示符）：
set npm_config_registry=https://registry.npmmirror.com
set npm_config_better_sqlite3_binary_host_mirror=https://registry.npmmirror.com/-/binary/better-sqlite3
npm install
```

## 六、给 AI 的三条命令

**用 AI 做课，先完整读 `skills/SKILL.md`**：它是从教学设计到上课的整套流程，会按顺序调用下面三条命令，并把每门课的设计、规格、进度都放在 `lessons/<id>/` 里。

帮教师生成课程的 AI 按这个顺序用（教师不用碰终端：工作台启动前会自动检查，第 3 步"用 AI 做课"的"备课进度"里也有"检查课程"按钮，结果可以"复制给 AI"）：

- `npm run new:lesson -- --id <id> --title <课名>`：在 `lessons/<id>/` 生成一门空课（`lesson.config.js`、`stages/`、`README.md`），并把 `.env` 的 `LESSON_CONFIG` 指向它（`--dir` 换目录，`--no-env` 不改 `.env`）。
- `npm run new:stage -- --lesson <lesson.config 路径> --id <id> --label <阶段名> --primitive <vote|quiz|free-text|code|data-analysis|none> [--after <已有阶段目录>]`：生成 `NN-<id>/` 阶段骨架（阶段卡 `STAGE.md` + 原语配置，或 `none` 的五个自写文件与测试）并写进课程的 `stages`，然后自动检查一遍；按阶段卡把 `TODO：` 占位填完。
- `npm run check:lesson [lesson.config 路径]`：检查课程写得对不对，每条给出 `文件:行`、一句话原因和"→ 怎么改"；有错误退出 1，`--json` 输出结构化结果。改到只剩"通过"（最多有警告）再交给教师启动。
- `npm run build:lesson -- [lesson.config 路径]`：把一门课的前端打包到系统临时目录，只为确认学生页能打开，不动工作台用的 `dist/`；末行"通过：页面能打包"或"打包失败"（退出 1），找不到配置退出 2。
